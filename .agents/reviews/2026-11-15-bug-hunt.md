# zuid bug hunt, 2026-11-15

Commit `df17861`. Hunters: 3 on Fable 5.2 (`fable`), run one at a time, each
shown only its own brief. Slices: (1) the R layer, (2) decoding, (3) what the
package emits and the state behind it, plus ownership. Coordinator on Opus
5.5: target map, re-runs, grading and filing.

Built here: macOS x86_64, R 4.6.2, Apple clang 17. That covers the
`__APPLE__` entropy branch, and the plain-C core alone under ASan and UBSan
(hunters 2 and 3).

Unverified: the `_WIN32` (`BCryptGenRandom`) and `__linux__` (`getrandom`,
`/dev/urandom`) branches of `src/zuid_entropy.c`; arm64 behaviour of the
`int64` overflow in #102; allocation-failure paths (no injection hook, #91).

Every finding below was re-run by the coordinator against a fresh install of
`df17861` (`2026-11-15-bug-hunt-probes/h1.R`, `h2.R`, `h3.R`). The probe
scripts use `HUNT_ROOT` for the scratch root: the directory holding `lib/`,
the package installed from `git archive df17861`.

Three bugs were filed earlier the same day, while writing
`.agents/assurance.md` (PR #100): #88, #89 and #90. Hunter 3 found all three
independently, without being told of them.

## 1. Re-seed every generator's state after fork — #88, #109, high, reproduced

- Where: [`src/zuid_r_gen.c:15-39`](https://github.com/pedrobtz/zuid/blob/df17861/src/zuid_r_gen.c#L15-L39),
  [`src/zuid_r_layout.c:13-30`](https://github.com/pedrobtz/zuid/blob/df17861/src/zuid_r_layout.c#L13-L30)
- Trigger: `objectid(1)`, then
  `parallel::mclapply(1:4, function(i) objectid(1000), mc.cores = 4)`.
  - ObjectId: 3000 of 4000 values are duplicates.
  - `uuid(50000, 1)` per child: 101,060 duplicates.
  - `ulid(1, time = t)` in two children: the same ULID.
  - `xid()` with a fixed `process =`: duplicates.
- Cause: the session-static state is copied by `fork()`, and nothing compares
  a PID.
- Fix: record `getpid()` with the state, and reset every static when it
  differs.
- Family: 2, state across `fork()`. Siblings checked: v4, v7, SCRU128, KSUID,
  NanoID, UPID and default `xid()` held, because each child draws fresh
  entropy.
- Test the suite lacked: a warm parent and two `mclapply` children at a
  frozen `time`, for every generator; assert no value is repeated.

## 2. Keep the clock apart from the emitted time — #101, high, reproduced

- Where: [`src/zuid_gen.c:38`](https://github.com/pedrobtz/zuid/blob/df17861/src/zuid_gen.c#L38),
  [`:50`](https://github.com/pedrobtz/zuid/blob/df17861/src/zuid_gen.c#L50),
  [`:76`](https://github.com/pedrobtz/zuid/blob/df17861/src/zuid_gen.c#L76),
  [`:250-254`](https://github.com/pedrobtz/zuid/blob/df17861/src/zuid_gen.c#L250-L254)
- Trigger: `scru64(100, node = 1, node_bits = 23)` at default options raises
  `zuid_clock_error` at value 82.
  - With `rollback = "reset"`, 200 values give 81 unique.
  - At `zuid.rollback_tolerance = 0`, `uuid(20000)` is not increasing, and
    `uuid(40000, 1)` has 7,232 duplicates.
- Cause: counter overflow moves the generator's own timestamp forward, and
  the next request is measured against it as if the clock had run back.
  Snowflake keeps `last_clock` apart and is correct.
- Fix: measure rollback against the last clock reading, not the last emitted
  time.
- Family: 1, one variable with two meanings.
- Test the suite lacked: `n` several times the per-tick counter capacity at a
  frozen `time`, at tolerance 0 and at the default, for every monotonic
  generator.

## 3. The 16-slot state tables evict live state — #89, #90, medium, reproduced

- Where: [`src/zuid_r_layout.c:13-27`](https://github.com/pedrobtz/zuid/blob/df17861/src/zuid_r_layout.c#L13-L27),
  [`src/zuid_r_gen.c:19-36`](https://github.com/pedrobtz/zuid/blob/df17861/src/zuid_r_gen.c#L19-L36)
- Trigger: one value under layout L, one under each of 16 others, then L
  again in the same tick. The second L value repeats the first.
  - SCRU64: with 17 nodes, node 0's next value is lower than its last.
- Cause: round-robin eviction by creation order. `n = 0` and failed calls
  still take a slot.
- Family: 3, an undocumented compiled limit with no straddle test.
- Test the suite lacked: 15, 16 and 17 other layouts or nodes between two
  calls at a frozen `time`.

## 4. Bound the tolerance options before the int64 cast — #102, medium, reproduced

- Where: [`R/conditions.R:50`](https://github.com/pedrobtz/zuid/blob/df17861/R/conditions.R#L50),
  [`src/zuid_r_gen.c:123`](https://github.com/pedrobtz/zuid/blob/df17861/src/zuid_r_gen.c#L123),
  [`:190`](https://github.com/pedrobtz/zuid/blob/df17861/src/zuid_r_gen.c#L190),
  [`:253`](https://github.com/pedrobtz/zuid/blob/df17861/src/zuid_r_gen.c#L253),
  [`src/zuid_r_layout.c:134`](https://github.com/pedrobtz/zuid/blob/df17861/src/zuid_r_layout.c#L134)
- Trigger: `options(zuid.clock_tolerance = Inf)` makes every `snowflake()`
  call raise `zuid_clock_error`. `zuid.rollback_tolerance = 1e12` makes
  `uuid(40000, 1)` return 23,616 duplicates.
- Cause: an out-of-range double cast to `int64_t` is undefined behaviour.
- Family: 3, only the lower bound is checked.
- Test the suite lacked: each tolerance option at `Inf` and near `2^63` ms.

## 5. Check the format's structure in `id_from_bytes()` — #103, medium, reproduced

- Where: [`src/zuid_fmt_scru.c:138-149`](https://github.com/pedrobtz/zuid/blob/df17861/src/zuid_fmt_scru.c#L138-L149),
  [`src/zuid_r.c:209-233`](https://github.com/pedrobtz/zuid/blob/df17861/src/zuid_r.c#L209-L233)
- Trigger: `id_from_bytes(as.raw(rep(0xff, 8)), "scru64")` gives
  `w5e11264sgsf`, whose bytes are `3a b9 a9 d5 5c ff ff ff`.
- Siblings: SCRU64 with the sign bit set, SCRU128 and SCRU64 at reserved
  timestamp 0, and a CID with a wrong digest length all build values that
  `id_parse()` rejects. Only the Snowflake sign bit is checked.
- Family: 3. Found by hunters 1 and 2.
- Test the suite lacked: for every fixed-width format, bytes in equal bytes
  out, or a classed refusal, at the maximum, maximum + 1 and reserved values.

## 13. Lower-severity findings

- **#112, low, reproduced.** `xid(process = Inf)` writes process 0;
  `sqids(min_length = NULL)` and an out-of-range `na` attribute raise
  unclassed errors.
- **#113, low, reproduced.** Cuid2's default level is looser than the
  reference `isCuid()` (71 of 922 cases). The docs are consistent with the
  code; the code comment is wrong.
- **#114, low, reproduced.** The layout epoch is printed 1 ms early. The
  UUID `"hex"` form contradicts two doc sentences (found by hunters 1 and 3).
  An error message depends on `OutDec` and `scipen`. The `nanoid()` docs say
  256 symbols. `uuid(7)` ignores `namespace` and `name`.
- **#115, low, reproduced.** `id_layout(fields =)` renames nested fields and
  accepts `=` and `,` in field names.
- **#116, question, inspection.** Snowflake state is looked up by `memcmp`
  over a struct with padding. Not reproduced on this build.
- **#97 (comment).** `id_decode()` has no size cap, so its output can be
  refused by `id_encode()`.

## Cross-cutting

- **Static state is a long-lived object, though nothing returns it.** Four
  of the findings (#88, #89, #90, #101) are in session-static generator
  state, and none of the inventories in `assurance.md` would list it: the
  standard's `lifecycle` kind is "returns objects outliving the call".
  Candidate rule for `correctness.md` family 2: *process-wide state in
  native code is a long-lived object; it gets the fork guard and a
  straddle test of any table that holds it, whether or not R ever sees a
  handle.*
- **Two routes to the same value, one guard.** #103, #106, #108 and #110
  are the same shape: `id_parse()` checks, and a sibling entry point
  (`id_from_bytes()`, `==`, text without the attribute, `id_decode()`)
  doesn't. That is family 3, and the R hunter's "two routes" probe found
  most of it.
- **A generator's state measured against itself** (#101) is family 1: the
  stored time means "last emitted" to the overflow code and "last clock" to
  the rollback check.

## Held: what was probed and stood

- **Byte codecs.** 50,052 cases over 11 forms and 9 caller alphabets
  against an independent big-integer oracle and the Python libraries, sizes
  0 to 1000 bytes, straddling every buffer switch: 0 disagreements. Niceware
  (65,536 words, 3,600 phrases), Proquint (500) and Uuid25: 0.
- **Fixed-width formats.** 28,208 decode cases against python-ulid,
  typeid-python, upid, scru128, scru64, svix-ksuid, pymongo and the stdlib
  `uuid`: no case accepted that the reference rejects, and no differing
  bytes.
- **Sqids.** 34,337 encodings and 26,021 decodes against Python sqids,
  including ids up to 7,379 characters around the 512 stack buffer.
- **CID.** 10,375 cases against Python `multiformats`; 9- and 10-byte
  varints.
- **Sonyflake.** 1,024 values against `sonyflake-py` `decompose`, up to
  2^64 - 1: 0 mismatches. That covers the oracle the assurance gap #94 asks
  for; the gap stays open until the suite has it.
- **Generators against references.** 181 values (v1, v4, v6, v7, v8, ULID,
  TypeID, UPID, SCRU128, SCRU64, KSUID, ObjectId, XID) and 134 Snowflakes
  under 7 layouts: every field matched.
  - SCRU128 and SCRU64 model differential: 122 of 123 timestamp walks
    matched; the one difference is SCRU128 refusing 2^48 - 1.
  - NanoID: 101 cases byte-identical to nanoid 6.0.2.
- **C core under ASan and UBSan.** 363,657 decoder and parser calls, and
  every generator at the time limits with tolerances up to `INT64_MAX`:
  clean.
- **R layer.**
  - Every generator rejects bad `n` and `time` with `zuid_type_error`.
  - Generators given `time` and `random` are pure.
  - `id_time()` round trips for all 11 time-bearing formats.
  - Vector operations keep layout and params.
  - A hostile session (`LC_ALL=C`, `tr_TR.UTF-8`, `OutDec`, `scipen`,
    `digits`, `warn = 2`, non-UTC `TZ`) changed 43 deterministic outputs in
    no way except #106 and one message (#114).
- **Ownership by inspection.** Every `malloc` is in the plain-C core and
  freed in the same function with no R call between. R allocations are
  protected at once.

## Not reached

- Windows and Linux entropy and clock branches.
- arm64 behaviour of #102.
- v7 and v1 overflow at the default tolerance inside R. That needs more than
  8 GB; it was reproduced in the C core only (#101).
- Allocation failure (#91). XID and ObjectId past 2^24 values per second.
- Interrupts: no C entry point checks for them, so there is no partial
  state to reach.
- Colliding CID, KSUID, XID and SCRU128 texts in detection: reasoned
  through, not run.

## Not reproduced, and by design

- Nothing a hunter reported failed to reproduce.
- By design, with citations:
  - CID text is kept as it arrived, so the same CID in two multibases
    compares unequal (design §6.5).
  - Digit-only strings detect as XID, ObjectId, SCRU128 or KSUID by length
    (the "exactly one passes" rule, design §6.2).
  - `sqids()` encodes only up to 2^53 - 1 (the 2026-10-24 scope cut, in
    `CLAUDE.md`).
  - Sqids are valid only under the `min_length` they were made with
    (`?id_parse`).
  - A future non-pure `time` moves the session forward ("a `time` that runs
    back is treated as the clock is", `?uuid`).
